# Selecting a team from project evidence

The default read for coordinated work. Team size follows the table in [SKILL.md](../SKILL.md#select-the-team); load other references only when their condition holds.

## Intake before people

Answer what changes the assignment: the outcome, project stage, where the problem occurs, settled decisions, and evidence that can establish success. Inspect a small set of authoritative files first. A Blender export does not by itself require a Blender specialist; a payments dependency does not turn a CSS fix into a financial audit.

The task and current sources outweigh old AGENCY.md suggestions. Preferred specialists are starting points, never a permanent roster. If scope is unclear, do useful independent inspection, then ask only what it cannot answer ([owner questions](../SKILL.md#make-work-visible)).

## Routing guide

| Need | First source of expertise | Reason to add another role |
|---|---|---|
| Product, UX, architecture, business or broad critique | agency-review and agency-agents personas | A distinct unanswered project question |
| Unity, Unreal, Blender, Maya, ZBrush or Godot | studio-experts wrapper and relevant roles | Another app actually needs source work or a handoff |
| Roblox and Luau | [Local Roblox division](roblox.md), shared safety overlay and revision-aware Creator Docs lookup | A distinct data/purchase, input, replication, QA or growth question |
| Fieldbook needing a team, fan-out or review-fix loop (market, household, project-state, entity or archive subject) | [Local Fieldbook division](fieldbook.md) over the `fieldbook` skill and its scripts | A distinct research track, a reader, or a critic lens the job needs; a plain build, audit, refresh or page edit uses the skill alone |
| Video, image, music, foley or voice-over work needing a team, handoffs or a queue | [Local Media division](media.md) over the project's own runtimes and `media_check.py` | A distinct team, or mix and delivery for a finished piece; `studio-experts` then takes the engine side |
| A page WebFetch and the archive cannot read, or a screenshot of a public page as evidence | [Web browser role](../roles/general/web-browser.md) under the [browsing contract](browsing.md); the built-in app browser pane is the coordinator's, for watched work or the owner's own sign-in | Open-ended research (Research division); sign-ins, forms or purchases (never) |
| Website/application implementation | Relevant installed implementation skill and actual stack | UX, security or performance justified by scope/evidence |
| A security audit of a codebase the owner controls | Cloudflare's security-audit skill (https://github.com/cloudflare/security-audit-skill), read by path at `security-audit-skill/skills/security-audit/SKILL.md`, pinned c1c8a8c, never installed | Only on an explicit audit request, and state the agent count first. It is source-first and defensive. On a host with no sandbox it gives leads, not confirmed findings: run each lead's local check as an ordinary test afterwards. Its validators need a wrapper on Windows |
| Research or uncertain knowledge | wiki query first; scoped research for a real gap | The wiki/research workflow calls for workers and budget |
| Documents, slides, sheets, media | Matching available production skill | Distinct subject-matter review or acceptance |
| Final wording of user-facing prose (copy, docs, emails, reports) | [Prose Humanizer](../roles/general/prose-humanizer.md) using the installed `humanizer` skill | The text reads as AI-written and only wording, not content, should change |
| Another skill set/repository | Provider intake in providers.md | A demonstrated gap and user-selected source |

The [workflow selector](workflow-routing.md) connects implementation, interface design, capability adoption, document extraction, editorial opportunities and AI visibility measurement to concrete outputs. New [local roles](workflow-routing.md#how-roles-and-workflows-run) are available as brief files through The Agency; they do not establish that an optional scanner, OCR runtime or graph tool is installed. Existing personas retain design, architecture, editorial and research ownership.

Do not pretend a skill is installed because it appears here. Use live session metadata and existing paths, then inspect the selected source. Do not install a plugin just to make the table true. Read each finalist's full skill, persona or role and its local safety overlay before dispatch; catalog matches are candidates, not a competence ranking ([providers.md](providers.md) has the catalog commands). Direct invocations of agency-review or studio-experts keep their own workflows.

## Decision record

For substantial work record this beside the deliverable, not in the permanent brief:

| Deliverable | Source evidence | Specialist and absolute path | Why this role | Execution available | Acceptance | Dependency |
|---|---|---|---|---|---|---|

Explain rejected alternatives only when plausible and consequential. Separate expertise fit from execution readiness. An animation expert can review source while playback is unavailable.

## Coordination functions

These are coordinator responsibilities, not mandatory agents or claims of new installed skills:

- Project intake: establish current facts and the next decision before selecting specialists.
- Evidence review: challenge important claims and keep acceptance levels distinct.
- Project continuity: carry durable decisions, current priorities and verified KB links into AGENCY.md.

Split one into a worker only when it has substantial independent work. Do not duplicate a product reviewer as an intake agent or add an evidence agent for a trivial edit.
